# Repository Guidelines

## Project Structure & Module Organization

- `src/main.jsx` contains the React UI and conversational flow; `src/styles.css` contains its styles.
- `index.html` is the Vite entry point. The legacy standalone page is kept as `AI体验中心指引页面 index.html（更新版）.html`.
- `server.js` provides the Express API, SSE streaming endpoint, static-file serving, request limits, and PostgreSQL audit logging.
- `agent-runtime.js` configures the DeepAgents/LangChain Qwen agent, prompt schema, tools, and session flow.
- `videos/` holds local demo media (`overview.mp4` and tool demos); it is intentionally ignored by Git.
- `dist/` is generated by Vite and should not be edited or committed.

## Build, Test, and Development Commands

Run `npm install` with Node.js 18+ to install dependencies. Use:

- `npm run dev` to start the Vite development server.
- `npm run build` to create the production frontend in `dist/`.
- `npm run check` to run Node's syntax check on `server.js`.
- `npm start` to build the frontend and start Express on `PORT` (default `3000`).

Copy `.env.example` to `.env` and configure `QWEN_API_KEY`, `QWEN_MODEL`, `QWEN_BASE_URL`, and `DATABASE_URL` before exercising agent endpoints. Keep `QWEN_ENABLE_THINKING=false` for Qwen3 models because the guide relies on forced structured tool calls.

## Coding Style & Naming Conventions

Use two-space indentation, semicolons, double-quoted JavaScript strings, and focused functions. Follow existing React function-component patterns and hooks. Use `camelCase` for variables/functions, `PascalCase` for React components, and `UPPER_SNAKE_CASE` for constants. Keep user-facing copy in the existing Chinese product voice and avoid unnecessary dependencies.

## Testing Guidelines

No automated test script is configured. Before submitting changes, run `npm run check` and `npm run build`; for UI or streaming changes, verify the primary flow in a browser and exercise `/api/health` plus both chat endpoints. Playwright is available for browser checks.

## Commit & Pull Request Guidelines

Existing commits are short and action-oriented (for example, `优化agent`). Keep commits focused, use an imperative subject, and explain behavior changes in the body when needed. Pull requests should describe the user-visible and API changes, list validation commands, call out required environment variables or database migrations, and include screenshots or a short recording for UI changes. Never commit `.env`, API keys, database credentials, videos, `node_modules/`, or `dist/`.

## Security & Configuration

Use only脱敏/虚构练习材料. Do not log secrets or sensitive business data. Treat Qwen input/output as externally processed data and keep PostgreSQL credentials in environment variables. Review audit payloads, SSE handling, and tool schemas carefully because they affect persisted sessions and model-controlled actions.
